## ⚡ 快速开始

> ❗ **不能双击 `main.html` 用 `file://` 打开**：CSS / 字体 / webpack chunk 会被 CORS 拦截，pdf.js worker 与 cmaps 也读不到。必须走本地 HTTP 服务。

| 方式 | 操作 | 是否需要 Node |
|------|------|--------------|
| **单文件 exe（推荐）** | 双击 `dist/InvoiceHelper.exe` | 否，零依赖，约 98 MB |
| **一键脚本** | 双击 `start.bat` | 有系统 Node 时用 Node，否则自动改用 exe |
| **便携服务** | `node portable-server.js` | 是（Node 20+） |
| **开发 / 局域网** | `node server.js` | 是（Node 20+） |

启动后打开 **<http://127.0.0.1:8000/>**，关闭命令行窗口即停止。

> 🔐 **单实例守卫（便携版 / exe）**：重复启动不会新开窗口或端口。第二次启动会探测 8000 上的 `/__healthz` 健康端点，确认是本程序在跑后直接打开浏览器到已有实例并退出。只有 8000 空闲、或 8000 被**其他程序**占用时才会真正启动（后者自动顺延 +1）。如需强制多开，设 `MULTI_INSTANCE=1`。

```bash
npm start          # = node portable-server.js
npm run start:dev  # = node server.js
```

<details>
<summary>📋 环境变量 & 环境要求</summary>

| 变量 | 作用 |
|---|---|
| `PORT=8000` | 起始端口；便携版占用时自动顺延（先探测是否本程序，是则复用），`server.js` 则直接报错退出 |
| `MULTI_INSTANCE=1` | 便携版 / exe 关闭单实例守卫，恢复「端口被占就顺延」的旧多开行为 |
| `NO_BROWSER=1` | 不自动打开浏览器（无人值守 / 服务器场景） |
| `HOST=0.0.0.0` | **仅 `server.js`**：显式开放局域网访问。默认只绑 `127.0.0.1`，开放前请确认防火墙与网络环境 |

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / 11（exe 为 x64） |
| 运行环境 | Node.js **20+**（构建单文件 exe 需要 **22+**，用到 Node SEA） |
| 浏览器 | Chrome / Edge（建议） |
| 磁盘空间 | 约 150 MB（含 exe） |

## 🔄 使用流程

```mermaid
flowchart LR
    A[📥 上传发票 / 行程单] --> B[✂️ 行程单半页裁剪]
    B --> C[🔍 自动合并 & 识别]
    C --> D[📄 生成报销单]
    D --> G["✏️ 强制确认窗口<br/>预览 + 核对票据日期]"
    G -->|超范围票据未修正| G
    G -->|确认无误| E[👁️ 生成并合并预览]
    C --> E
    E --> F[🖨️ 打印 / 下载]
```

| 流程 | 步骤 |
|------|------|
| **基本打印** | 上传 → 自动合并 A4 双联 → 预览 → 打印 / 下载 |
| **混合票据** | 上传发票 + 打车行程单 → 右下角「行程单半页裁剪」面板查看裁剪日志 → 合并 |
| **报销单** | 填写出差范围 / 地点 / 补贴 → 点「生成报销单」→ **强制确认窗口**：报销单预览本身就是编辑画布，点击日期行 / 金额格直接修改对应票据 → 把 ⚠ 超范围票据的「归行日期」改到出差范围内（或调整上方出差范围）→ 「确认生成」→ 与发票合并 → 下载 / 打印 |

> ⚠️ 只有一个生成入口「📋 生成报销单」，点了必先打开确认窗口，**不确认不会生成任何 PDF**；生成成功后「⬇️ 下载」才可用（只下载已生成的那份，不会重复生成）。超范围票据未修正时「确认生成」默认禁用；确属跨期票据可勾选「我已核对，允许保留超范围票据」后显式放行。人工改过的项目名 / 金额 / 归行日期会缓存，下次生成继续生效。
>
> 裁剪配置（目标宽高比、底部留白、开关）存在 `localStorage`，**改完设置需重新上传文件**（结果有缓存）。

## 🧠 工作原理

票据的**识别、裁剪、合并、打印全部在浏览器端完成**，服务端只负责吐静态文件：

- **文本提取**：`pdf.js` 读 PDF 文本层，正则匹配「价税合计 / 小写 / 支付金额 / 票价」等字段。扫描件（无文本层）无法识别。
- **行程单裁剪**：`trip-crop.js` 包装 `Blob.prototype.arrayBuffer`，在字节进入任何环节前用 pdf.js 定位内容底部、用 pdf-lib 改写 `CropBox`。合并逻辑发现 `cropBox.height < mediaBox.height * 0.95` 时按裁剪区嵌入，因此缩放系数约 `0.475 → 0.950`，内容放大近一倍。
- **坐标归一化**：部分票据 CropBox/MediaBox 坐标颠倒，读取前统一修正，避免预览倒置。
- **PDF 合并**：`pdf-lib` 把每张票据嵌入 A4 版面（每页 2 张），报销单利用奇数页空白区拼接。
- **零上传**：基于 `File API` + `ArrayBuffer`，关闭页面即清除。

## 🧳 便携版与离线说明

**结论：可以完全离线。** 前端是纯静态站点，服务端只有 Node 内置模块的百来行代码，没有数据库、没有后端 API、没有原生插件。

### 离线化改动

- `static/vendor/`：html2canvas 1.4.1、jsPDF 2.5.1、pdf-lib 1.17.1 随项目自带
- `static/js/pdf.worker.min.mjs`：本地 worker（同时改掉 `pdfjs-lib.js` 的默认值与 `_initialize()` 重置点）
- `static/cmaps/`（169 个）+ `static/standard_fonts/`（16 个）：pdf.js 中文字符映射与标准字体
- 断网实测：外部请求 0；真实票据上传 → 报销单生成 → 合并 PDF 全链路通过

### 构建单文件 exe

```bash
npm run build:exe
# 或 node build-exe.js
```

产物 `dist/InvoiceHelper.exe`（Windows x64，约 98 MB）。原理是 Node 22 SEA：把 `main.html` + `404.html` + 图标 + `static/` 共 243 个文件（约 10.15 MiB）作为 assets 嵌进 `node.exe` 的 PE 资源节，运行时用 `node:sea.getAsset()` 读内存，不释放临时目录、不需要 Node、不需要联网。构建配置 `sea-config.json` 与临时入口都生成在 `.workbuddy/build/`（构建产物，不进源码根目录）；`postject` 只在构建期临时装到该目录，不污染项目依赖。

> ⚠️ Node SEA 的 `embedderRequire` **只认内置模块**，不支持 `require('./xxx.js')`。所以构建脚本会把 `safe-path.js` 内联成 `.workbuddy/build/portable-server.bundle.js` 作为 SEA 入口。**源码仍只有一份**：`server.js` 直接 require 原文件，exe 拿到的是构建期内联的副本。改动 `safe-path.js` 或 `portable-server.js` 后必须重新 `npm run build:exe`。
>
> ⚠️ `main.html` 与 `static/**` 也是**构建时嵌入**的资产。改过前端代码（例如报销单确认窗口）后，用 `dist/InvoiceHelper.exe` 日常使用时必须重新构建，否则 exe 里仍是旧页面。用 `node server.js` / `npm start` 跑源码目录则实时读盘，无需重建。

> ⚠️ postject 改写 PE 后原 Node 数字签名失效，构建会提示 `The signature seems corrupted!`，首次运行可能被 SmartScreen 拦截。**本定制版仅供本人自用，不得对外分发**（见许可证）。

> 🎨 构建产物已内置**自定义文件图标**与**中文版本信息**（产品名、描述、版权等，右键「属性」可见）。由 `tools/set-exe-metadata.mjs` 在 `build-exe.js` 第 6 步用纯 JS 的 `resedit` 写入，无需任何外部原生工具；图标源为 `apple-icon.png`，自动生成多尺寸 `app-icon.ico`。启动横幅也换成了带配色的清爽版本。

> 🪟 想要**双击无黑色控制台窗口**的纯净形态？用 `GUI=1 node build-exe.js` 重新构建即可。GUI 模式下服务在后台静默运行并自动打开浏览器；退出请访问启动横幅里打印的 `http://127.0.0.1:8000/__quit?token=…`（token 每次启动随机生成，防止网页偷偷关停服务），或在任务管理器结束进程。默认仍为带美化横幅的控制台模式（关闭窗口即停止）。

### 三种形态对比

| | `dist/InvoiceHelper.exe` | `start.bat` + 源码目录 | `node server.js` |
|---|---|---|---|
| 拷贝即用 | 单文件 | 整目录（约 10 MB） | 整目录 |
| 需要 Node | 否 | 是（或随包 `runtime\node.exe`） | 是 |
| 需要联网 | 否 | 否 | 否 |
| 默认监听 | `127.0.0.1` | `127.0.0.1` | `127.0.0.1`（可 `HOST` 开放） |
| 端口占用 | 自动 +1 | 自动 +1 | 报错退出 |
| 适用场景 | 日常使用 | 开发调试 | 局域网 / Nginx 前置 |

## 📦 部署方式

<details>
<summary><b>本地 / 局域网</b></summary>

```bash
node server.js
# 仅本机：http://127.0.0.1:8000/

# 需要局域网访问时显式开放：
#   Windows:  set HOST=0.0.0.0 && node server.js
#   POSIX:    HOST=0.0.0.0 node server.js
# 然后访问 http://<本机IP>:8000/，并确认防火墙放行
```

`server.js` 默认只绑回环地址，这是刻意的安全默认值；开放到局域网前请确认网络可信。
</details>

<details>
<summary><b>Nginx / Apache 前置</b></summary>

项目附带 `nginx.conf` 与 `.htaccess`，均已把默认入口改为 `main.html`、旧 `/index.html` 重定向到功能页。使用前修改 `root`、`server_name`、SSL 证书路径，然后 `nginx -t && nginx -s reload`。

静态托管时请保证 `.mjs` 返回 `text/javascript`、`.bcmap` 可被读取，否则 pdf.js worker 与中文映射表会失效。
</details>

| `verify-recognition.js` | **识别规则**回归（唯一不依赖浏览器的一项）：伪造 pdf.js 文本层，把受控票面喂给 `extractInvoiceDataFromPdf`，锁死住宿票三种排版（携程「入住…」/ 同程「入住日期：」/ 直营无日期）、跨年离店、网约车备注含酒店名不误判住宿、铁路票两种出行日写法、日期紧贴时刻不被吞、只印「交通运输服务」的客运票、机票行程单不得判行程单/不得进打的费、归类优先级（人工 > docKind > 关键词）、混合票按明细行拆分（含含税/不含税两种排版、项目名被 pdf.js 拆成多段仍能切行、认不全不拆、双交通不拆、机票不拆）、金额可信度分级（价税合计/全票唯一金额/打分猜测）与两源金额仲裁（55 项） |
| `verify-real-nanning.js` | 用 10 份真实票据的**固化识别结果**回归报销单逻辑：住宿票进住宿列、客运班车票进车船费-其他、入住日/出行日归行、区间推断不吃开票日（61 项） |
| `verify-pdf-assets.js` | 零依赖校验真实 PDF 的文件结构、页数、页面尺寸与文本流存在性（45 项） |

> 📐 **实测结论**：本批 2 份行程单都是 A4 竖版 `595.3×841.9pt`，裁剪前提成立；8 张发票均非 A4。早期批次的 **`滴滴出行电子发票.pdf` 曾是 A4 竖版**且文件名命中平台关键词，会被误裁掉下半页。现已加两道防线：文件名标明「电子发票 / 增值税 / 发票号码」直接跳过、内容接近整页直接跳过（仅明确写「行程单」的文件名豁免），并固化为回归用例。

> ⚠️ **重要**：`verify-real-nanning.js` 里的 10 份票据金额 / 日期是浏览器里识别后**固化的常量**，脚本本身**不解析 PDF**。所以「全部测试通过」**不等于**「PDF 文本提取正确」。为此新增 `verify-recognition.js`：它不读 PDF，而是用受控**票面文本**驱动 `extractInvoiceDataFromPdf`，把识别规则（住宿/客运/铁路/机票、归行日来源、归类优先级）锁进 CI；仍未覆盖的是 pdf.js 从真实 PDF 取文本这一段，那部分只能在浏览器里用真票验证（`verify-trip-detection.html`）。

> 🧪 **真票浏览器验证页**：打开 `/verify-trip-detection.html`（**仅源码模式**；发行版 exe 不内置，避免把会打印票面信息的诊断页一起分发），一次选中待验 PDF，页面会用**与主程序完全相同**的 pdf.js + cMap 配置调用 `extractInvoiceDataFromPdf`，逐票列出 `isTrip` 判定、金额、命中的票面关键词（铁证 / 弱词分开标注），再把结果喂给 `buildTripModel` 给出报销单汇总，并自动跑一组不变量检查（如「文件名写行程单必须判行程单」「有带金额价税合计必须判发票」「南宁 10 票合计须为 271.18 元、住宿费 48 元、车船费-其他 175 元」）。可一键复制诊断报告。改动 `pdf.js` / 字段正则 / 分类判定后，用它跑一遍真票即可闭环——Node 离线还原不了真票的自定义 cmap 文本层，这一步只能在浏览器里做。
>
> ⚙️ **它怎么拿到 pdf.js**：`static/js/pdfjs-lib.js` 是 Next.js 的 webpack chunk，脱离主程序单独加载时 `window.pdfjsLib` 恒为 `undefined`（本页曾因此把全部票据判成「提取失败、金额 0」）。现在本页挂一个隐藏 iframe 载入 `main.html`，借用它已跑通的 pdf.js / cMap / worker 配置，跨 realm 传 `File` 时再用 iframe 的构造函数重包一次字节，避免 pdf.js 报 `Invalid PDF binary data`。
>
> `2026-9 南宁/` 内的 10 份 PDF 含真实公司名、金额与行程，属于隐私数据，**不要随源码目录分享**（已由 `.gitignore` 排除）。

## ❓ 常见问题

<details>
<summary><b>要注册 / 联网 / 安装吗？</b></summary>

不需要注册，也不需要联网。双击 `dist/InvoiceHelper.exe` 或 `start.bat` 即可，全程本机处理。仅在使用 `node portable-server.js` / `node server.js` 时需要 Node.js。
</details>

<details>
<summary><b>上传的票据会泄露吗？</b></summary>

不会。票据在浏览器本地处理，不上传、不存云端，关闭页面即清除。服务端只提供静态文件，绑定 `127.0.0.1`，不接收任何票据数据。
</details>

<details>
<summary><b>识别不准 / 行程单没被裁剪怎么办？</b></summary>

- PDF 需含**可提取文本层**，扫描件、加密或损坏文件无法解析
- 展开右下角「行程单半页裁剪」面板看日志：会写明是被裁剪还是跳过，以及跳过原因（非 A4 竖版 / 文件名标明发票 / 内容接近整页 / 旋转页 / 无文本层）
- 裁剪比例不合适可在面板里调「目标宽高比」「底部留白」，**改完需重新上传文件**
</details>

<details>
<summary><b>点「生成报销单」没反应 / 提示超范围票据？</b></summary>

现在所有生成入口都会先弹出确认窗口，不会直接出 PDF。窗口左侧是实时报销单预览，金额格里带**彩色发票图标 + 金额小 chip**（🚕 打车 / 🚌 客运 / 🎫 车票 / 🏨 住宿 / ↩️ 退票）；右侧是**行程卡片网格，默认打开「全部票据」**——按金额核对关系把行程单和发票配成一张卡，行程单作凭证条、发票可逐张编辑。

- **票据数恒等于上传文件数**：同一个 PDF 在识别缓存里会同时存在「文件名键」和「文件指纹键」两条记录，直接取缓存会把「上传 10 个文件」算成 20 份票据。确认窗口取数时按**文件身份 + 金额**归一后再去重，保证「发票数 + 行程单数 = 上传文件数」，统计卡片与确认窗口口径完全一致。
- **行程卡片**：**以行程单为容器**——行程单金额与一组发票金额之和严格相等时，这几张发票（1~N 张）归到这张卡的凭证条下；没有行程单的发票各自单独成卡。**整张卡按费用类别着色**——顶部是实色标题带（图标徽章 + 类别名 + 金额），卡体是同色淡底，另有类别边框，**五类费用一眼可分**；顶部「全部票据」下方有色卡图例。卡片右上金额一律取**组内发票金额之和**，📋 凭证条上的行程单金额只作分组依据、标注「仅分组依据」，既不写入格子也不进合计；没有发票认领的行程单会单独成灰色卡提示，含超范围票据的卡带红色「⚠ 超范围」角标。
- **拖拽填入**：直接把右侧整张卡或卡内某张发票**拖到左侧报销单的日期/金额格**，即可把该票归到那一天、填入那一列；拖到补贴列无效（补贴按天数自动算）。拖拽本质是改「归行日期 / 填入位置」，与手动编辑完全同源。
- **拖动已填入的 chip**：报销单金额格里那些彩色 chip 也能直接拖——拖到别的日期/费用列格即可把该票挪过去，改完预览和合计立即刷新。
- **移出表格**：把 chip（或右侧卡片）**拖回右侧票据区**，会出现红色「移出」投放提示，松手后该票从报销单移除：chip 消失、金额不再计入合计，「待处理」也不再报它。票据仍留在右侧卡片里并标记灰色「已移出」，**把它拖回任意格子即可恢复计入**。不想拖拽的话，点开该格编辑面板里的「🗑 从报销单移出」按钮效果相同。移出状态会缓存到下次生成。
- **预览即编辑**：点击预览里的日期行、金额格或某个 chip，会弹出「这张格子由哪些票据组成」的面板，直接改项目名 / 金额 / 填入位置 / 归行日期；空格子还能把票据「移入」。改完预览立即刷新，右侧对应卡片会同步高亮。
- 顶部红色横幅列出超范围票据的日期与笔数；点「定位第 1 笔」直接打开对应票据的编辑面板，「待处理」标签只显示含超范围票据的卡片。
- 在编辑面板或卡片的「归行日期」里选一个出差范围内的日期，或用「放入出差日期…」快捷下拉，预览的「超范围」行会立即消失。
- **归行日期怎么来的**：住宿票取**入住日**、旅客运输票取票面**出行日期/乘车日**、其余票取**开票日期**（卡片上分别写「按入住日 / 按出行日 / 按开票日期归行」）。携程代订住宿票、汽车票常常是行程结束后统一开票，按开票日归行会直接落到出差区间外被误报超范围，所以优先用票面真实消费日。
- 「填入位置」下拉（普票费 / 打的费 / 其他 / 住宿费 / 退票费）：系统自动归类，若归错可手动改，改后金额实时挪到所选列；手动选择会缓存，下次生成继续生效。自动归类先用**识别阶段给出的票据类型硬结论**（住宿票 / 客运班车票），再退回项目名关键词——携程这类代订住宿票的项目名是「生产生活服务*经纪代理服务*代订住宿费」，只靠关键词会被兜底成「车船费-其他」，所以住宿票一律先按 docKind 定死进住宿列；汽车站/运输集团/公共交通的客运票同理先定死进「车船费-其他」，不会被「客运服务费」这个网约车关键词抢进「打的费」。
- **金额存疑的「!」标记**：金额框右侧出现橙色小圆点，鼠标悬停会说明原因——①票面没印「价税合计（小写）」，金额是从票面文字推测的；②识别结果与解析器给出的数对不上。系统只在票面写出法定总额（价税合计 / 全票唯一金额）或行程单核对金额时才让识别结果拍板，其余情况宁可用别的解析器的数、并把分歧摆给你看，绝不静默只用一个。手工改一次金额即视为已核对，该票不再提示（下次生成也不会再提）。
- 右上角可切换「分栏 / 预览 / 票据」；窄屏默认只看预览，点「票据」再展开卡片网格。
- 若确实是跨期出差，改上方的「出差范围」起止日期即可；实在要保留跨期票据，勾选底部「我已核对，允许保留超范围票据」后显式放行。
- 全部修正前「确认生成」是禁用的；点「取消」/ ESC / 窗口空白处不会生成任何文件。

</details>

点击文件旁的「复制」创建副本，副本会改尾部字节使 MD5 变化，绕过打印系统的重复文件校验。

## 🔧 故障排除

<details>
<summary><b>页面空白 / 加载失败</b></summary>

- 确认服务已启动，且访问的是 `http://127.0.0.1:8000/` 而不是 `file://`
- 按 F12 检查控制台资源加载错误，确认 `static/` 目录完整
- 改过 chunk 或 CDN 本地化配置后按 `Ctrl+F5` 强刷（服务端已设 `no-store`，一般不需要）
</details>

<details>
<summary><b>端口被占用</b></summary>

- 便携版 / exe 默认**单实例**：再启动一次只复用已有 8000 实例并打开浏览器，不会开新窗口。反复双击却弹出多个窗口，是旧版本遗留的多开实例，关掉多余窗口即可（新版已根治）
- 8000 被**其他程序**占用时，便携版 / exe 会自动顺延到 8001、8002…；`server.js` 会直接报错退出
- 指定端口：`set PORT=3000 && node server.js`（exe / 便携版同用 `PORT` 环境变量）
- 查占用：`netstat -ano | findstr 8000`
- 强制多开（调试用）：`set MULTI_INSTANCE=1 && node portable-server.js`
</details>

<details>
<summary><b>局域网访问不了 / exe 被拦</b></summary>

- 局域网：必须用 `HOST=0.0.0.0 node server.js`（默认只绑回环地址），并放行防火墙
- exe 首次运行被 SmartScreen 拦：属无签名产物，自用可点「仍要运行」
- 打印无反应：确认浏览器未阻止弹窗，或改用下载后手动打印
</details>
